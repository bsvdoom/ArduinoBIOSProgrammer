MANDATORY SAFETY RULES
Use only a separate, expendable test chip.
Do not connect this setup to a motherboard.
Assume that all existing data on the test chip may be destroyed.
Never apply 5 V to a flash pin rated for the 3 V supply range.
Use appropriate level shifting between the 5 V Arduino Uno signals and the flash.
Use a common ground.
Place a 100 nF ceramic decoupling capacitor close to the flash VCC and GND pins.
Change wiring only while all power sources and USB are disconnected.
Do not guess the pinout from the package orientation.
Do not assume that a chip advertised as “W25Q128” is a particular W25Q128 variant.
Stop if the marking, package, pinout, voltage, capacity, or JEDEC identity is uncertain.
Never run erase or write automatically.
Require a separate explicit user confirmation immediately before erase.
Require another separate explicit user confirmation immediately before write.
Do not interpret an earlier confirmation as authorization for a later destructive operation.
Do not automatically retry a failed erase or write.
Do not modify production code during this validation.
If a software defect is found, preserve the evidence and stop. Fix it in a separate development session so the validation baseline remains unchanged.
Do not push, merge, tag, publish a release, or alter repository visibility.

Capacity.
JEDEC manufacturer and device identification.

PHASE 2 — PHYSICAL PRE-POWER CHECKLIST
Ask the user to confirm every item separately:
Arduino USB and all other power sources are disconnected.
The flash is outside the motherboard.
The package orientation and pin 1 were identified from the exact datasheet.
VCC and GND are not reversed.
CS#, DO/MISO, WP#, GND, DI/MOSI, CLK, HOLD#/RESET#, and VCC match the exact datasheet.
WP# is held at the required defined level.
HOLD#/RESET# is held at the required defined level.
Arduino and flash have a common ground.
A 100 nF ceramic capacitor is fitted close to flash VCC and GND.
All Arduino-to-flash output signals pass through suitable level shifting.
There is no short circuit between flash VCC and GND.
The expected voltage at every flash pin is within the datasheet limits.
The user accepts that the test chip may be erased or damaged.
Do not apply power until every item is confirmed.
Codex cannot physically verify wiring or voltage. Treat the user’s physical inspection and measurements as required external evidence.

PHASE 6 — TWO INDEPENDENT INITIAL READS
Create the validation workspace outside the Git repository.
Do not store validation binaries in a tracked project directory.

Exit code.
Complete program output.
Resulting file size.
SHA-256 hash.
Require:
Both files are exactly 16,777,216 bytes.
Both SHA-256 hashes are identical.
Byte-for-byte comparison succeeds.

Page and erase-block boundaries match.
Neither file is truncated or padded.
Also count:
Total 0xFF bytes.
Total non-0xFF bytes.
Do not assume that a new chip is blank.

Preserve both files and logs outside Git.
PHASE 7 — DETERMINISTIC VALIDATION IMAGE
Create a deterministic test image outside the repository.
Requirements:
Exact size: 16,777,216 bytes.
It must not be a BIOS image.
It must be reproducible from a documented algorithm and fixed seed.
It must contain all possible byte values.
It must vary across 256-byte pages.
It must detect byte-pair swaps.
It must detect page swaps.
It must detect erase-block swaps.
It must detect shifts, truncation, padding, and stuck 0x00 or 0xFF regions.
A suitable approach is to generate the stream from consecutive SHA-256 blocks using a fixed ASCII domain string, an incrementing 64-bit counter, and deterministic concatenation until the exact capacity is reached.
Record:
Generation algorithm.
Fixed domain string.
Exact file size.
SHA-256 hash of the completed image.
Do not add the image or generation output to Git.

PHASE 12 — POWER-CYCLE VERIFICATION
After the first successful verification:
1. Close all serial-port users.
2. Disconnect Arduino USB.
3. Disconnect all flash power.
4. Confirm that the circuit is unpowered.
5. Reconnect the unchanged circuit.
6. Initialize the programmer again.
7. Run the same explicit CLI verify operation again.
Require the second verification to produce the same successful result and matching SHA-256 hash.
Do not automatically erase or rewrite after power cycling.
